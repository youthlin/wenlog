# Blog Browser Verify

适用于 `youthlin/blog` 仓库的本地启动 + 浏览器验收流程。

## When to use

在以下场景使用：

- 用户要求“实际运行项目看看效果”
- 用户要求“打开浏览器验证改动”
- 用户要求检查前台 `/`、后台 `/admin/login`、后台 `/admin/` 的真实页面表现
- 用户要求确认主题切换、语言切换、样式协调性、截图效果

## Instructions

1. **先确认仓库位置**
   - 当前仓库工作目录应为：`/data00/home/youthlin.chen/go/src/github.com/youthlin/blog`
   - 除非用户明确要求，不要切换到别的仓库执行。

2. **准备管理员账号**
   - 先执行：
     ```bash
     go run ./cmd/server/main.go -set-admin "admin:admin123456"
     ```
   - 这样可以确保后续浏览器登录后台时有稳定账号可用。

3. **启动服务**
   - 用 `go run ./cmd/server/main.go` 启动服务。
   - 如果 agent 运行环境支持后台进程，启动后持续检查 `http://127.0.0.1:8888/healthz`，直到返回成功。
   - 若 8888 已被当前仓库服务占用，优先复用；若不是本仓库实例，再处理冲突。

4. **验证前台页面**
   - 打开：`http://127.0.0.1:8888/`
   - 重点检查：
     - 主题下拉是否存在且可切换
     - 语言下拉是否存在且可切换
     - `切换主题` 这类辅助文案是否仅保留为屏幕阅读器文本，而不是可见文案
     - 不同主题，尤其是亮色主题，是否在背景、页头、强调色、卡片层次上确实有区别
   - 如用户要求语言验证，至少检查：
     - `/?lang=zh_CN`
     - `/?lang=en_US`

5. **验证后台登录页**
   - 打开：`http://127.0.0.1:8888/admin/login`
   - 重点检查：
     - 语言下拉是否存在且切换生效
     - 主题下拉是否存在且切换生效
     - 登录页视觉与主题是否一致

6. **验证后台主页**
   - 用账号 `admin / admin123456` 登录后台。
   - 登录后打开或停留在：`http://127.0.0.1:8888/admin/`
   - 检查：
     - 后台头部主题切换是否生效
     - 后台语言下拉是否生效
     - 导航、卡片、表单、按钮在不同主题下是否协调

7. **优先使用浏览器自动化做客观校验**
   - 如果环境可用，优先用 Playwright/Chromium 或当前 agent 的浏览器工具完成：
     - 切换不同主题并读取实际样式值
     - 切换语言并读取实际文案
     - 截图保留验收证据
   - 若 Node 环境无法直接 `require('playwright')`，可尝试：
     - `npx playwright --version`
     - 从 `~/.npm/_npx/**/node_modules/playwright` 复用模块
   - 不要因为第一次浏览器调用失败就放弃，应继续寻找可行方案。

8. **建议最少覆盖的浏览器验收项**
   - 前台：
     - 默认主题
     - 至少 2 个亮色主题（例如 `light`、`red-plum`）
     - 中英文切换
   - 后台：
     - 登录页中英文切换
     - 后台主页至少 2 个主题切换
     - 后台主页语言切换

9. **输出验收结果时要具体**
   - 说明访问了哪些 URL
   - 说明验证了哪些主题/语言
   - 明确指出是否发现问题
   - 如果有截图，说明截图对象和结论
   - 如做了代码修复，引用具体位置，使用 `file:line` 形式

10. **收尾检查**
    - 若用户要求提交前验证，再补跑：
      ```bash
      go test ./...
      ```
    - 若用户没要求提交，不要主动 commit。
